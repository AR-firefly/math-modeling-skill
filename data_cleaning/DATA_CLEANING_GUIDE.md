# 数据清洗指南（DataCleaner 六方案 + 自动择优）

> 核心理念：**不拍脑袋选一种清洗方式**。AI 同时尝试全部方案，用客观指标对比，
> 选分布保留最完整的，并把选择理由写进 process_record 与论文"数据处理"小节。
> 对应代码：`src/math_modeling/data_cleaner.py`

## 一、六方案速查表

| 策略                      | 做法                       | 适用场景                            | 副作用                   | 何时禁用                    |
| ------------------------- | -------------------------- | ----------------------------------- | ------------------------ | --------------------------- |
| `mean` 均值填充           | 缺失列全局均值             | 数值型、缺失少、分布对称            | 压缩方差、拉向中心       | 偏态/含离群值               |
| `median` 中位数填充       | 缺失列全局中位数           | 偏态分布、含离群值                  | 扭曲形状、丢失尾部       | 缺失成片                    |
| `group_median` 分组中位数 | 按 group_cols 分组取中位数 | 有明确分组（区域/品类），组间差异大 | 需先选对分组列           | 无分组信息时退化为不处理    |
| `knn` KNN 填充            | 用最相似 K 个样本均值      | 多维相关结构、缺失值与其他列相关    | 依赖其他列质量、计算量大 | 样本过少 / 其他列也大量缺失 |
| `zero` 零填充             | 填 0                       | 缺失本身有业务含义（"无记录=0"）    | 人为制造虚假 0 值        | 缺失≠0 的普通数值列         |
| `drop` 删行               | 删除含缺失的行             | 缺失比例极低（<1%）                 | 信息损失、样本量下降     | 缺失比例高                  |

## 二、对比标准（谁更好）

`DataCleaner.compare()` 每策略输出三个指标，择优顺序：

1. **KS 分布保留度（ks_stat）**——填充后与原始非缺失值做 KS 检验，**统计量越低 = 分布保留越完整**（首选）
2. **方差变化（var_change）**——填充前后方差相对变化，越小越好（不扭曲分布）
3. **填充数（filled）**——实际填充了多少缺失值（仅供参考，不算好坏）

择优规则：`ks_stat` 最小者胜；平手时方差变化小者胜。

## 三、决策流程（AI 必须走全，不准跳过）

```
发现缺失列
  └─> DataCleaner(df)                       # 传入 group_cols / target_cols
       └─> apply_all()                      # 同时跑 6 种策略
            └─> compare()                   # 量化对比：方差/KS/填充数
                 └─> best()                 # 自动选分布保留最优
                      └─> reason()          # 生成选择理由
                           ├─> rec.log("数据清洗", reason)    # 进 process_record
                           └─> 论文"数据处理"小节引用          # 进论文
```

**要点**：

- 清洗**不是一次性的**：每个后续环节发现新缺失/异常值，回到此流程重新探索
- 清洗结果**必须可复现**：随机算法固定 seed=42
- 理由必须**可写进论文**：`reason()` 输出自带数据（KS、方差变化、填充数），照抄即可

## 四、与论文的衔接

- `reason()` 的输出直接写进论文"数据处理/数据预处理"小节（`build_paper_content` 的 `clean_reason` 参数）
- 评审看"数据怎么处理的、为什么这么处理"——六方案对比 + 客观指标 = 严谨证据链
