# process_record 规格 —— 心路历程写作标准（skill 最精华的产出，v3.0）

> 现行阶段、来源、创新、人工声明及交付边界见 `../references/执行与交付契约.md`；原细则在当前阶段范围内执行，不代替团队第一问批准或全文独立终审。

> 定位：这是 **skill 最精华的产出物** 的规格。`output/process_record.md` 是 AI 完整可核验决策摘要与实验记录，
> **≥500 行**，交人复盘用，与论文并列，不是附属品。人拿着它回放 AI 思路、逐段对照优化。

## 1. 核心定位

| 项     | 标准                                                                                         |
| ------ | -------------------------------------------------------------------------------------------- |
| 地位   | **整个 skill 最精华的产出**，不是可选的记录                                                  |
| 篇幅   | **≥500 行**（保底，内容完备优先，宁可超不可少）                                              |
| 用途   | 交用户/队伍复盘，人对照着优化论文                                                            |
| 事实   | 基于**执行 Agent 试错日志 + 审查日志 + results/** 整合，**禁止编造**任何试错过程、数字、理由 |
| 可溯源 | 每个关键结论能追到：试错日志 → results 字段 → 代码出处                                       |

## 2. 详略分配（13 节怎么写）

| 层级             | 节                   | 要求                                     |
| ---------------- | -------------------- | ---------------------------------------- |
| **写透（最重）** | 思考轨迹（试错链）   | 每问完整六步链，见第 4 节                |
| **写透（最重）** | 算法取舍（算法心路） | 候选→淘汰→选中→比较，见第 5 节           |
| **写透（最重）** | 文献借鉴             | 逐篇文献"参考了什么+怎么用"，见第 5.5 节 |

| **保底实写**     | 其余 9 节            | 每节有实内容，非填空、非"（无内容）"     |

## 3. 核心重点表（写透级，必须覆盖）

| 重点                   | 落在哪节            | 写透到什么程度                                   | 内部质量审查用途    |
| ---------------------- | ------------------- | ------------------------------------------------ | ------------------- |
| 不同算法对比           | 算法取舍            | 候选算法清单 → 逐候选评价 → 淘汰 → 算法比较表    | 算法选择与创新证据  |
| 不同策略间模型对比     | 思考轨迹 / 对比验证 | 每问试错链中呈现，含基线对比（改进前后效果量化） | 基线对比（铁律4）   |
| 为什么选这个模型的理由 | 算法取舍逻辑链      | 淘汰理由 + 选中理由 + 验证逻辑链                 | 建模理由/假设合理性 |
| 有关摘要的东西         | 数值归因            | 摘要结果性数字按指标/单位定位 results 字段       | 摘要证据完整性      |
| 参考了什么文献         | 文献借鉴            | 每篇来源 + 参考了它的什么 + 怎么用 + 效果        | 建模创造性/参考文献 |

**这四项是提分核心，任何一项缺了 = 不达标。**

## 4. 试错链六步（思考轨迹节，核心中的核心）

每问逐项说明以下六类可核验记录；没有实际失败或改进如实注明，不能为凑六步编造：

```
怎么想 → 试了什么 → 结果如何 → 在哪撞墙 → 怎么改进 → 最终效果
```

| 步           | 写什么                                                                 |
| ------------ | ---------------------------------------------------------------------- |
| **怎么想**   | 这问核心难点？第一反应用什么方法？为什么？                             |
| **试了什么** | 实际跑了什么（算法/模型/参数/数据范围），代码或产物在哪                |
| **结果如何** | 跑出来的数字/现象，符合预期吗？                                        |
| **在哪撞墙** | 哪里不对、哪里算不出、哪里不符合物理常识。真实失败详记，未发生如实注明 |
| **怎么改进** | 换算法/换假设/调参数/简化模型，为什么这么改                            |
| **最终效果** | 改进后结果，与改进前对比（提升多少/解决什么问题）                      |

多策略/多模型对比就在这一步呈现：基线 vs 改进，效果量化。

## 5. 算法心路详规（算法取舍节）

skill 旧要求只记"选了什么、弃了什么"。本规格要求**完整逻辑链**：

1. **候选算法清单**：这问适合哪些算法（保底 + 加分，从 `algorithms/` 索引找），逐候选列出。
2. **逐候选评价**：每个候选——原理一句话、适用条件、对本问适配度、复杂度、预期效果。
3. **淘汰理由**：被淘汰的候选，为什么（数据不满足前提 / 复杂度不可行 / 精度不够 / 与别问冲突）。
4. **选中理由**：最终选中的，为什么（适配数据特征 / 可解释 / 精度与效率平衡）。
5. **算法比较表**：候选 vs 选中横向对比（适用条件 / 复杂度 / 结果 / 优劣）。
6. **验证逻辑链**：这个选择用五样检验里的哪几样证明了（对比验证 / 误差分析 / 数值收敛）。

## 5.5 文献借鉴节写法（写透级，v2.1 新增）

每篇被参考的文献一张卡片，四要素缺一不可：

1. **来源**：共享语料路径（`SHARED_PAPERS_DIR/...`，语料保留在 v2.0 目录、不在本仓库）或 原始发表来源标题、准确链接及 DOI
2. **参考了它的什么**：模型结构 / 算法思想 / 论证方式 / 写法框架 —— **具体到哪一部分**（不许写"参考了它的方法"这种空话）
3. **怎么用到本赛题**：赛题场景下怎么套用/改造，为什么适用
4. **用了之后效果**：思路打通 / 结果提升多少（与"没参考会怎样"对照）

> 对应门禁0 文献调研报告 §四 的逐篇文献卡片——解题时参考的文献从这里来，写作时把它写进本节。
> 禁止编造来源：每篇文献必须真实（已核验原出处与书目信息，失败状态不当通过）。

## 6. 13 节逐节要求（每节写清"这节要呈现什么才算实"）

| 节               | 写清什么才算实                                                  |
| ---------------- | --------------------------------------------------------------- |
| 赛题判断         | 每问判断为 优化/评价/预测/机理 哪类，依据（数据形态、题目要求） |
| 数据清洗         | 六方案对比 + 择优理由 + 丢弃/修正了什么、为什么                 |
| 算法取舍         | 见第 5 节（算法心路详规）                                       |
| 文献借鉴         | 见第 5.5 节（逐篇文献：来源/参考了什么/怎么用/效果）            |
| 思考轨迹         | 见第 4 节（试错链六步），每问展开                               |
| 灵敏度           | 参数扰动变化幅度排序，哪些敏感、影响多大                        |
| 不确定点         | 存疑假设 / 待定参数 / 影响多大 / 如何验证                       |
| 可优化方向       | 换算法/加数据/深化论证，各方向预期收益                          |
| 人工审核方向     | 必须人才能审的点（[ ] 清单），交用户                            |
| 数值归因         | 论文数字 ↔ results 字段 ↔ 代码出处，双向可溯源（见第 8 节）     |
| 论文参考与风险点 | 参考了哪些优秀论文、为什么、查重风险点清单、参考文献来源        |
| 复现             | run_manifest.json 路径（seed + SHA-256）                        |
| 断点             | 当前阶段 / 下一步                                               |

## 7. 结果表述（跨节要求）

- **关键结果优先用图文/图承载（图 + 一句结论），避免大段纯文字。**
- 不是"图越多越好"——是**关键结论用图/图文表达，让评审一眼抓到重点**。
- 图表服务于结果解释与证据表达，宁可少而精，不要多而糙。

## 8. 摘要溯源（数值归因节）

- 摘要每个结果性数字按指标/单位/条件反向定位到 results/；年份/编号/常量分类说明依据。
- 数值归因节建表：数字 ↔ results 字段 ↔ 代码出处（文件 + 位置）。
- 任何摘要数字没有出处 = 一票否决项，交前必查。

## 9. 与生成器的关系

- `src/math_modeling/process_recorder.py` 自动生成 process_record **骨架**（13 节 + 试错链 stage 标签）。
- AI 的任务：把骨架**填成 ≥500 行的完整决策与实验记录**，按本规格写透核心重点。
- 生成器 stage 标准（`log_trace`）：怎么想 / 试了什么 / 结果如何 / 在哪撞墙 / 怎么改进 / 最终效果（兼容旧：题型判断 / 算法尝试 / 撞墙 / 改进 / 算法取舍 / 验证）。

## 10. 阶段与真实性补充

第一问仅记录真实完成范围，全文最终验收13节至少500行；六类记录中未发生失败或改进如实说明，不造过程、不灌水，不要求内部隐含思维链。逐图在文献借鉴/复现节登记准确官方链接、示例/API、代码和数据入口、运行方式、版本、修改及理由。历史日志恢复保留原文，不可解析项标未知。

**作图日志的引用（13 节结构不变，作图内容并入「复现」节，不新增第 14 节）**：
本节「复现」节登记逐图信息时，来源为作图 Agent 的 `docs/log_作图.md`（多模态目视检查记录：每图发现的问题 + 修正）与 `figures/figures_manifest.json`（脚本 / 数据入口 / PNG / `artifact_hash` / 状态）。process*record **只引用、不复制**作图日志全文——把每图的「脚本路径 · 数据入口 · 绑定 results 键 · 状态 · 目视结论」写成一行可核验条目，具体检查过程留在 `docs/log*作图.md`供审查 Agent 独立复核。审查侧`docs/log\_审查.md` 的独立观察项同样不并入本文件，避免把审查记录写成被审对象的自证。
