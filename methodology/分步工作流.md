# 数学建模全流程分步工作流

> 现行阶段、来源、创新、人工声明及交付边界见 `../references/执行与交付契约.md`；原细则在当前阶段范围内执行，不代替团队第一问批准或全文独立终审。

两阶段包络：全题理解后，以下Phase步骤先应用于第一问完整交付；报告经团队明确批准后再应用于剩余问题与全文。Phase5仅做实现简化，不开展逐问强制创新；TRIZ按统一契约时机。

完整工作流：**领域理解 → 头脑风暴 → 计划 → 资源调查 → 实现求解 → 简化优化 → 验证确认 → 论文生成 → 自评验收**

> **与 SKILL.md 六角色+门禁的关系**：本文件是执行操作细节（建模手/编程手/作图手/论文手/信息检索手/审查手通用），角色分工与门禁见 `SKILL.md`——
> 信息检索手产出**证据轨**（`docs/检索证据卡片/` + `docs/log_信息检索.md`）→**门禁0（仅证据轨）**；建模手产出文献调研报告→**门禁0** + 建模文档（含核心建模选择论证）→**门禁1**（独立 Subagent 审计）；编程手产出 results/ + 五样检验→**门禁2a**；作图手产出 `figures/`（脚本+数据入口+PNG+manifest+改图指南）→**门禁2b**；论文手产出 paper.tex + risk_points.md→**门禁3**；论文写作质量按 `references/论文自评表.md` **三层自评** + 优秀论文横向对照→**门禁4**；process_record 对照规格→**门禁5**。
> 每阶段产物过对应门禁后再进下一阶段，门禁由独立 Subagent / `scripts/stage_gate.py`（第一问即可跑）/ `scripts/gate_audit.py`（仅全文，可机检项）执行，不是 run_all 内嵌。

## Phase 0：问题理解

**目标**：保证人和AI对问题的理解一致。

**你要做的**：

- 把题目原文发给 AI
- 说清楚背景和约束

**AI 做的**：

- 复述问题理解，确认没有歧义
- 判断题型（优化类/评价类/预测类/机理类）
- 评估规模（小 n≤15 / 中 n≤100 / 大 n>100）

**输出**：问题理解确认书（一段话，你点头了再往下）

---

## Phase 0.5：文献调研（门禁0，解题前置）

**目标**：既有方法引用原始文献，原创推导有数学依据与独立验证，禁止编造。

**AI 做的**：

- 按 `references/文献调研报告模板.md` 产出文献调研报告：
  ① 多源检索（本地匹配优秀论文与允许的学术原始来源，失败标待核验，不切换排除来源）
  ② 六维评分粗筛（题型匹配 gate，<10 自动拒）
  ③ 逐篇文献卡片（来源/方法/借鉴点/怎么用）
  ④ 核心建模选择预登记（每问计划方法 ↔ 文献出处）
- 产出 → **门禁0**（独立 Subagent 审计：检索来源可查、评分 gate 执行、出处完整）

**门禁0依据审查**：已有方法有原出处；原创选择有推导与独立验证计划，不能凭缺少先例直接否决。

**你做的**：

- 审报告：文献来源真实、方法贴合赛题

## Phase 1：头脑风暴（Brainstorming）

**目标**：发散思路，不做决定。

**AI 做的**：

- 给出 2-3 种可行技术路线
- 每种路线说明：思路 + 优缺点 + 预期效果
- 不评估哪种更好——那是你的决定

**你做的**：

- 听完所有方案
- 选一个方向，或者组合

**关键**：这个阶段不写代码。只聊天。

---

## Phase 2：制定计划（Plan）

**目标**：确定实现方案，列出步骤。

**AI 做的**：

- 根据你选的方向，出具体计划：

```
计划包含：
├─ 做什么（一句话）
├─ 技术方案（算法选型 + 理由）
├─ 涉及文件清单
├─ 实现步骤（分步，每步可独立验证）
├─ 验证方法（怎么确认每步正确）
└─ 需要你做什么
```

- 算法选型参考 `算法选型指南.md`

**你做的**：

- 审核计划
- 说"行"或者调整

---

## Phase 3：资源调查（找 Skill）

**目标**：不重复造轮子。

**AI 做的**：

- 检查已有 skill 库是否有可复用的
- 检查当前项目代码中是否有可复用的函数
- 报告：找到了什么 / 没找到要新建什么

**你做的**：

- 决定复用还是新建

---

## Phase 4：实现求解（Implement）

**目标**：按计划写代码、跑结果。

**AI 做的**：

- 一次实现一个模块
- 每完成一个模块跑通验证
- 记录结果到 `results/`

**分步模式**（推荐）：

```
Step 4.1: 配置和数据准备
  写 config.py, utils.py → 验证数据正确

Step 4.2: Phase1 求解
  写算法代码 → 跑通 → 记录结果

Step 4.3: Phase2 求解
  ...

Step 4.4: Phase3 求解
  ...

Step 4.5: Phase4 求解
  ...
```

**你做的**：

- 第一问完整交付后明确批准；其他实际疑问及时确认
- 卡住了告诉 AI 调整

---

## Phase 5：简化优化（Simplify）

**目标**：减少冗余、提高效率。

**AI 做的**（简化审查四个维度）：

| 维度 | 检查内容               |
| ---- | ---------------------- |
| 复用 | 有没有重复实现已有功能 |
| 简化 | 有没有不必要的复杂逻辑 |
| 效率 | 有没有可优化的性能问题 |
| 深度 | 改动在正确层级吗       |

---

## Phase 6：验证确认（Verify）

**目标**：每一项改动的表面可观察验证。

**AI 做的**（可观察验证）：

1. **找变化**：确认改了什么
2. **找表面**：这个改动的用户界面是什么（CLI输出/图表/文件）
3. **驱动它**：跑最小路径让改动代码执行
4. **推它**：边界情况测试
5. **捕获**：记录所有输出

**验证 ≠ 跑测试**。验证 = 跑真的场景看实际输出。

---

## Phase 7：论文生成

**目标**：按规范生成竞赛论文。

**AI 做的**：

- 参考 `写作心法.md` 规范 + `references/国赛论文规范2026.pdf`（格式合规）
- 深度参考**共享语料**（`SHARED_PAPERS_DIR`，语料需自备、不在本仓库）中的对应题型论文（结构/论证/表述）
- 用 `run_all.py` / `build_paper_content` 生成结构化论文（**TeX 单渲染**，数字从 results/ 取，verify 零 issues）；图来自作图手交付的 `figures/`（论文手不改图，改图走 `references/改图指南.md`）
- 论文手产出 → **门禁3**（独立 Subagent 审计：verify 零 issues + 六角色日志齐全 + 查重风险点清单 + 国赛规范对齐 + AI 使用声明与详情 PDF 指引）

**你做的**：

- 检查论文内容
- 按 `output/risk_points.md` 改写规避查重
- 正式提交前删除任何身份/学校信息（国赛规范）

---

## Phase 8：自评验收

**目标**：确认交付物质量。

**AI 做的**：

- 对照 `写作心法.md` 逐项检查：

```
□ 标题：不用"基于XX"——直接用原题
□ 摘要：总分总 + 加粗结果
□ 问题分析：不出结果，只讲思路
□ 模型假设：~4条，以简化系统为主
□ 符号说明：三线表，≤半页
□ 模型格式：决策变量→目标→约束→大括号
□ 无吊书袋
□ 分级不超过三级
□ 表题在表上方、图题在图下方（国赛规范：表上图下）
```

- 安全扫描：确认无敏感信息泄露
- 整体评分 + 改进建议

**你做的**：

- 最终审核
- 说"行"或者"改"
