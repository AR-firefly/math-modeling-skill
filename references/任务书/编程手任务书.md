## 日志格式（强制）

每条记录以时间戳开头，格式 `[YYYY-MM-DD HH:MM]`，后接六步链任一环节标签：

- **[怎么想]** 这问核心难点？第一反应用什么方法？
- **[试了什么]** 实际跑了什么（算法/模型/参数/数据范围）
- **[结果如何]** 跑出来的数字/现象，符合预期吗？
- **[在哪撞墙]** 哪里不对、算不出、不符合物理常识（未发生如实注明）
- **[怎么改进]** 换算法/换假设/调参数，为什么
- **[最终效果]** 改进后结果，与改进前对比

- **算法心路必须完整**：候选算法清单 → 逐候选评价 → 淘汰理由 → 选中理由 → 算法比较表 → 验证逻辑链。
- 撞墙记录（数值不收敛 / 算不动 / 结果不符合物理常识 / 浮点问题）是最有价值的素材。
- 这是主 Agent 写心路历程的事实来源，**禁止事后编造**。

## 注意事项

- **先做不依赖建模的**：数据清洗、代码框架、选型研究可以先启动，不等建模文档（并行协议）。
- 复杂度权衡：精度与速度平衡，算得动优先；**超时标准：单次求解 >30min 或全程 >2h 须提前报告**；降精度或砍检验须用户同意。
- **交前完整重跑**：提交前由你执行完整重跑并贴输出（对应需求文档 §10 检查清单第 1 项）。
- 简单优先：numpy/pandas/scipy 优先，不堆算法；数值稳定性（大数小数、浮点精度）注意。
- 你的 results 会过**门禁2a**（审查 Agent 审），对照 `references/Subagent质检.md` 门禁2a 标准自查。
- **不画图**：作图归**作图手**（`作图Agent任务书.md`）；你只提供 results 数据入口与算好的误差数据，不写绘图脚本、不跑 `validate_figures.py`。
