## 2. 硬约束（最高优先，违反 = 全删重来）

1. **不擅自查文件（白名单，五项，目录级授权）**：只读 ① 赛题文件 ② `SKILL_ROOT` ③ **共享语料目录**（`references/优秀论文/` 指向的 v2.0 语料，常量 `SHARED_PAPERS_DIR` + 环境变量 `MM_SHARED_PAPERS` 定位，**不复制、不可删移**）④ 需求文档目录内全部任务书与协议 ⑤ 工作目录已产生的产物——**但 `docs/情报/` 除外**：该目录是情报轨隔离区（不可验证内容，见 §2 附则），**任何执行 Agent 不得将其作为输入读取**，仅主 Agent 与人工查看。不读、不找、不碰其他任何文件。
   > 新增任务书放在 `数学建模需求文档/` 内，被这层目录级授权自动覆盖；跨 `SKILL_ROOT` 读共享语料由第 ③ 项显式授权。
2. **受控联网（限信息检索 Agent）**：按Skill执行与交付契约定向查官方库文档/示例、学术原始论文、政府科研原始数据；指定两例外仅约定用途且不扩展外链，禁止第三方教程和自媒体。**联网授权归属信息检索 Agent**；**每轮必须写 `docs/log_信息检索.md`，无日志=未检索**。
3. **有歧义先问**：执行前 / 执行中遇到不明确处，先问清楚再动手，绝不猜。
4. **违规后果**：违反上述任何一条，用户会删掉全部产出、从头再来。

**决策留痕**：本决策经 2026-09-10 讨论确认，计划起草方已提示「赛中浏览当届赛题讨论 → 取消评奖资格」的风险；使用者选择自行把握。**不得在后续版本中删除本警告或本节留痕。**

### 双轨隔离（信息检索 Agent 产出分轨，必须遵守）

信息检索 Agent 的产出**分两条互不相通的轨道**，分界线是「**有没有独立的第三方可核验出处**」：

| 轨道       | 内容                                                    | 可验证性     | 流向                                                                 |
| ---------- | ------------------------------------------------------- | ------------ | -------------------------------------------------------------------- |
| **证据轨** | 学术原始论文（有 DOI/作者）、官方库文档与 API、官方通知 | **可验证**   | **正常喂给门禁0**，作为建模手文献调研报告的输入                      |
| **情报轨** | 第三方解析、他人思路、讨论帖、历年复盘                  | **不可验证** | **完全隔离**，落盘 `docs/情报/`，**任何执行 Agent 不得作为输入读取** |

**为什么必须隔离**：不可验证信息进入上下文后，会以「另一个 AI 已如此想过」的形式**伪装成证据**，而执行 Agent 无法判断其可信度——这比单纯的"上下文污染"更严重，是**用未经验证的内容充当判断依据**。证据轨有六维评分 + DOI 核验 + 逐篇卡片；情报轨**一概没有**，因为它不是证据。

**情报轨搜集什么（给人看、给人对答案，不喂 agent）**：同类题的公开解法、本届思路讨论、方法对比、赛后复盘、工具实战用法。每条须写清来源链接、内容摘要、**可参考的点**、**存疑的点**（只报好消息的情报是危险的）。

**隔离机制（4 条，必须写进契约）**：

1. 落盘 `docs/情报/`（与 `docs/检索证据卡片/` **物理分开**）
2. 契约写死：**该目录仅限主 Agent 与人工查看；任何执行 Agent（建模/编程/作图/论文）不得将其作为输入读取**
3. **释放时点由人决定**：主 Agent **只提醒不主动推送**，在两个节点报告「情报区有 N 条新内容」——① 第一问交付后 ② 全文完成后
4. **呈现给人，不喂给 agent**：对应「方便人对答案」的原始需求，由人的判断承担

## 3. 并行协调协议（可并行准备 + 必须串行的真求解链）

五个执行 Agent **同时启动**，各自独立上下文、各加载 skill 对应文档，靠**落盘文件交接**。**但只有准备工作可并行，真求解链必须串行**：

> **歧义处理（子 Agent 不直接问用户）**：主 Agent 是唯一交互口。执行 Agent 遇到硬约束 3「有歧义先问」的不明确处，**不直接问用户**，而是把歧义写入 `docs/人工审核方向.md` + 自己的试错日志（标注"待确认"）；主 Agent 落盘插审时收集，统一整理后一次性问用户，用户答复后由主 Agent 转发给对应 Agent。影响求解的疑问暂停相关工作，由主Agent问团队；只继续不依赖该决定的准备。

**① 可并行准备（启动即做，不等别人）**：

- **编程手**：数据清洗、搭代码框架、算法选型研究（不依赖建模文档的部分）。
- **论文手**：问题重述、问题分析、模型假设等不依赖 results/ 的草稿。
- **每个 Agent 实时写试错日志**：怎么想 → 试了什么 → 结果如何 → 在哪撞墙 → 怎么改进 → 最终效果，落盘（主 Agent 写心路历程的事实来源）。

**② 必须串行的真求解链（严格依赖前序）**：

- 交接链：文献调研报告（门禁0）→ 建模文档（门禁1）→ results/（门禁2a）→ 论文（门禁3）。
- 编程手逐问真解必须基于建模文档（门禁1 过）；论文手只引用 results/ 真实数字（门禁2a 过）。
- **别误以为能全并行提速**——求解链卡在门禁1→2→3 的串行依赖上，并行的只有准备工作。

## 5. 任务流程（各实际阶段内执行）

第一阶段只完成第一问，下列流程完成后交第一问报告等待明确批准；第二阶段再开展依赖后续各问与全文。不能把列举的逐问链误解为未经批准跑完全题。

0. **门禁0 文献先行**：建模手先产出文献调研报告（本地匹配优秀论文 → 允许的学术原始来源定向检索 + 六维评分 + 逐篇文献卡片 + 核心建模选择预登记）；六维评分"题型匹配"用**初步题型判断**（粗判优化/评价/预测/机理，Phase0 正式确认）；核心选择须有既有文献或原创推导与验证依据，既有方法补原出处；原创推导须依据及独立验证（阻断在建模前）。
1. **Phase 0 问题理解**：复述赛题理解、判断每问题型（优化/评价/预测/机理四类）、评估规模，交用户点头再往下。
2. **数据清洗**：按 `data_cleaning/DATA_CLEANING_GUIDE.md` 六方案对比择优，记录选择理由。
3. **逐问求解**：按题型检索 `algorithms/0X_*/`，套赛题数据**真解**（不是占位实现）。（在项目solver/prepare回调中实现真解，不修改只读Skill中的演示函数；实际检验和灵敏度亦由项目实现。）
4. **五样检验**：网格无关 / 数值收敛 / 灵敏度 / 误差分析 / 对比验证，逐类判断适用性；适用项有证据，不适用项有理由并经独立审查认可。
5. **灵敏度分析**：单参数 / 多参数联合扫描。
6. **论文生成**：按写作心法 + 深度参考 `references/优秀论文/` 写初稿，**TeX 单渲染**（只出 `paper.tex`，不生成 `.docx`；在线 Overleaf 为首选编译路径，本地 XeLaTeX 为兜底，两者都不可用标「待编译验证」，不伪造编译成功）。
7. **查重风险点**：自审产出 `output/risk_points.md`，人工按清单改写规避。
8. **过程记录**：产出 `output/process_record.md`（由**主 Agent** 基于各执行 Agent 试错日志整合，见第 7 节，精华）。

**产物**（全写工作目录，SKILL_ROOT 只读）：`results/`（results.json + run_manifest.json）、`figures/`、`output/`（paper.tex、process_record.md、risk_points.md）。

**落盘路径约定**（建模手/编程手/作图手/信息检索 Agent/论文手/审查 Agent 统一遵守，全写工作目录，供交接与门禁取用）：

### 日志格式（强制，六个写日志角色统一）

每条记录以时间戳开头，格式 `[YYYY-MM-DD HH:MM]`，后接六步链任一环节标签：

- **[怎么想]** 这问核心难点？第一反应用什么方法？
- **[试了什么]** 实际跑了什么（算法/模型/参数/数据范围）
- **[结果如何]** 跑出来的数字/现象，符合预期吗？
- **[在哪撞墙]** 哪里不对、算不出、不符合物理常识（未发生如实注明）
- **[怎么改进]** 换算法/换假设/调参数，为什么
- **[最终效果]** 改进后结果，与改进前对比

落到 6 个写日志的角色：建模手 / 编程手 / 论文手 / 审查 Agent / 作图手 / 信息检索 Agent，分别落盘 `docs/log_建模手.md`、`docs/log_编程手.md`、`docs/log_论文手.md`、`docs/log_审查.md`、`docs/log_作图.md`、`docs/log_信息检索.md`。**主 Agent 不写 `log_*.md`**（产出是 `output/process_record.md`），本文件不适用该格式。

## 6. 审查协议（谁在什么时机审什么）

| 时机                                                                                                       | 谁审           | 审什么                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 门禁节点（文献先行 / 建模定稿 / **代码可跑 2a** / **图可复现 2b** / 论文成稿 / 论文质量 / process_record） | **审查 Agent** | 对照 `Subagent质检.md` 七门禁标准终审（门禁0 文献先行·原创推导须依据及独立验证、门禁1 建模含核心建模选择论证、**门禁2a 代码可跑**（results 真解/五类检验/seed/manifest）、**门禁2b 图可复现**（脚本独立运行/无统计推断/契约齐全/数值与 results 一致/目视检查）、门禁3 论文成稿、门禁4 论文质量·对照优秀论文写法/评审维度、门禁5 process_record·对照 `process_record规格.md`）→ 出终审报告 |
| 执行 Agent 落盘产物时                                                                                      | **主 Agent**   | 抽查关键点（数字溯源 / 完整性 / 日志真实性）                                                                                                                                                                                                                                                                                                                                              |
| 终审全复核                                                                                                 | **主 Agent**   | 审查 Agent 终审报告 → **复核审查报告 + 全面自审七门禁关键项**，双审双绿                                                                                                                                                                                                                                                                                                                   |

**门禁2 拆分为 2a / 2b（保留编号，两个独立 Subagent 分审）**：

- **2a 代码可跑（编程 Agent）**：results 真解 / 五类检验 / seed=42 / run_manifest SHA-256 / 工具回归与 pytest。**画图与 validate_figures 预检已移出 2a，归 2b**（避免双写）。
- **2b 图可复现（作图 Agent）**：脚本独立运行 / 无统计推断 / 契约齐全 / **图数值与 results 一致** / **目视检查**。原门禁2 的「画图脚本过 `validate_figures` 预检（中文字体/禁 rainbow/jet/hsv/DPI≥300），FAIL 已修」**逐字保留，原样移入 2b**。

**两个角色的审查区别（避免重复 / 推诿）**：

- **主 Agent 落盘插审**：轻量、随时、抽查——产物是否落盘、数字能否溯源、日志是否真实，只做"有没有明显问题"的快速把关，发现问题先报对应 Agent，**不代替正式验收**。
- **审查 Agent 门禁终审**：正式、深度——七门禁（2 拆 2a/2b）逐项对照 `Subagent质检.md` 全查，出终审报告，是**独立审查结论，需与主Agent自审共同通过**。
- 两者均留具体证据，最终自审与独审均须通过；过程抽查不代替最终自审。

**审查 Agent**：按 `审查Agent任务书.md` 执行——门禁节点终审七门禁（2 拆 2a/2b），出审查日志 + 终审报告，通过才提交主 Agent。**不负责持续盯**（落盘插审归主 Agent）。

**主 Agent**：落盘产物插审（抽查关键点）+ 终审全复核（**复核审查报告 + 全面自审七门禁关键项** + **process_record 整合完整 ≥500 行按规格**）。整理终审清单交用户，用户点头才算提交。

**审查纪律（最重要，最高约束）：基于事实判断，不吹毛求疵。**

- 每个问题必须附**具体事实依据**：哪个数字（results 字段）、哪段代码（文件 + 位置）、哪条 skill 要求没满足（引用条目）。
- 没有事实依据的质疑**不计入问题**，不据此修改。
- **真实问题才算问题**；宁可漏报疑点，不编造问题。

**循环条件**：问题 → 报回 → 修复 → 复核，循环到审查 Agent 终审 + 主 Agent 终审全复核双全绿。

## 7. 思考细节文档（process_record）——整个 skill 的精华

这是**全流程最重要的产出物**，交用户和队伍复盘用。主 Agent 负责最终整合。

- **精华定位**：这是整个 skill 最精华的产出，不是可选记录。
- **篇幅**：**≥500 行**（保底，内容完备优先）。
- **事实来源**：基于执行 Agent 试错日志 + 审查日志 + results/ 整合，**禁止编造**。
- **整合策略**：主 Agent 读试错日志的**关键节**（撞墙 / 改进 / 算法心路）而非全量原始日志（避免膨胀上下文），据此产出**仍 ≥500 行**、每问试错链六步写透的完整决策与实验记录；抽查 results/ 关键数字核对。
- **规格**：按 `methodology/process_record规格.md`（SKILL_ROOT 下）写——**13 节**逐节要求（含「文献借鉴」节，逐篇写清参考了什么+怎么用）、试错链六步、算法心路详规、核心重点表（算法对比 / 模型对比 / 选择理由 / 摘要溯源）都在里面。

细节全部在 skill 规格文件里，此处不重复。

## 8. 复现与事实铁律

- **seed=42 固定**；元启发式跑 3 次报均值±标准差（标明误差定义）。
- **run_manifest.json** 含 seed + 输入文件 SHA-256。
- **论文结果性数字按指标/单位/条件从 results/ 取，非结果数字分类核验**，verify 技术强制校验，零 issues。
- 结论：**跑通才算完，没跑通 = 没做完**。

---

## 9. 效率与优先级

- **代码运算效率要重视**：仿真精度与速度平衡，算得动优先；超时提前报告；降精度或砍检验须用户同意。
- **但最关键的永远是 process_record**：求解数字是"果"，心路历程是"因"。所有 Agent 的试错日志、审查日志、每次改进都要如实记录——这才是 skill 的精华所在。

## 10. 提交前检查（终审清单交用户）

双全绿后，主 Agent 整理**终审清单**交用户，**用户点头才算提交**：

- [ ] 程序能跑（交前完整重跑验证，由**编程手**执行完整重跑并贴输出）
- [ ] 结果性数字按指标/单位/条件有代码证据，与论文一致；年份/编号/常量分类核验
- [ ] 五类检验适用项证据齐全，不适用项经独审认可（网格无关 / 数值收敛 / 灵敏度 / 误差 / 对比）
- [ ] 每问结果一一列出、可比较
- [ ] 摘要数字可溯源到 results/
- [ ] process_record 按 `methodology/process_record规格.md` 写，13 节完整（含文献借鉴节）+ 试错链 + 算法心路（≥500 行）
- [ ] 文献调研报告已产出，核心选择有既有文献或原创推导与验证依据（门禁0 已过，原创推导须依据及独立验证）
- [ ] 核心判定模型有物理论证 + 替代方案数值对比记录（门禁1「核心建模选择必论证必对比」已过）
- [ ] risk_points 已生成且人工处理状态如实列入独立待办，不能由AI自行宣称已处理
- [ ] **作图过门禁2b**：绘图脚本可脱离 run*all 独立运行、不含统计推断（AST + 运行时守卫）、契约齐全、**图数值与 results 一致**（插桩比对）、**作图手已逐图多模态目视自检**（记录在 `docs/log*作图.md`），审查 Agent **独立看图**（在 `docs/log\_审查.md` 写下作图手记录中未出现的观察项；与作图手记录完全一致且无独立观察视为未独立查看）
- [ ] **检索过门禁0（仅证据轨）**：`docs/检索证据卡片/` 可查、六维评分与逐篇卡片齐全；**情报轨 `docs/情报/` 完全隔离**（任何执行 Agent 未作为输入读取）；`docs/log_信息检索.md` 逐轮齐全
- [ ] 论文过门禁4（写作质量·对照优秀论文写法/评审维度）、process_record 过门禁5（对照规格）
- [ ] seed 固定、可复现
- [ ] 无敏感信息

上述是团队提交确认；AI自身交付须实际证据和双审通过，人工声明待填不冒充已填。明确区分AI交付完成、第一问待批准和团队可提交。
