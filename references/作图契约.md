# 作图契约 —— 作图 Agent 必读（含机检口径）

> 现行阶段、来源、创新、人工声明及交付边界见 `执行与交付契约.md`；原细则在当前阶段范围内执行，不代替团队第一问批准或全文独立终审。
> 本文件与 `图表规范.md`（选图决策表 §一、配色 §三）、`改图指南.md`（改图与重跑）、`执行与交付契约.md` §3（官方资料与交付）互为分工：**本文件管"图能不能被机器验证"**，`图表规范.md` 管"图该怎么画"。

> 借鉴 nature-figure（nature-skills，Apache-2.0，见 NOTICE.md）的 **Figure Contract** 思想。
> 核心：**每张图是一个视觉论证，不是孤立的漂亮图**。画图前先写契约（证明什么、证据从哪来、什么图、编号、图题），再写代码。
> v3.0 在此基础上再进一步：契约从"给人看的五问"升级为**"给机器验的结构"**——`CONTRACT` 元数据 + `data_binding` 映射 + 状态机。

## 一、图分类（两类，豁免范围不同）

| 类         | 内容                                                                    | 判定字段                               | 可机检性                                 |
| ---------- | ----------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------- |
| **数据图** | 含实测数值（折线/柱状/散点/箱线/热力/直方/误差棒/等高线/雷达/区间填充） | `data_binding.kind = "data"`（缺省值） | **可机检**：数值可从 `results/` 逐值比对 |
| **示意图** | 流程图、框架图、机理示意（节点 + 箭头 + 文本，无数值）                  | `data_binding.kind = "schematic"`      | **无数值可比**：豁免数值比对             |

**豁免范围（只此两条，不得扩大）**：

| 检查项                                                            | 数据图 | 示意图                           |
| ----------------------------------------------------------------- | ------ | -------------------------------- |
| 脚本独立可运行 / 300dpi / 禁 rainbow / 中文字体 / `__file__` 定位 | 必查   | **必查**（不豁免）               |
| manifest 必填字段齐全                                             | 必查   | **必查**（不豁免）               |
| 禁统计推断（AST + 运行时守卫）                                    | 必查   | **必查**（不豁免，见 §六说明）   |
| `data_binding` 字段存在                                           | 必查   | **必查（显式声明 `schematic`）** |
| `data_binding.bindings` 逐值比对（验收③）                         | 必查   | **豁免**（无 results 键可绑）    |

**三条纪律**：

1. **缺省从严**：`kind` 未声明 = 按**数据图**全量检查。示意图必须**显式写出** `kind: "schematic"`，不允许用"不写"来自动豁免。
2. **豁免不等于不做**：示意图仍须过脚本硬规范、状态机与目视检查，只是没有"数值一致"这一项。
3. **分类维度不冲突**：本表按**可机检性**分类；`图契约.md` 的"诊断图/对比图/论文图/附录图"按**用途**分类。两者正交，一张图同时有"用途"与"类型"两个标签。

## 二、目录分层与路径语义

```
figures/
├── scripts/fig03_sensitivity_paramA.py     # ASCII 语义名
├── data/fig03_sensitivity_paramA.json      # 脚本读取的数据入口（可执行脚本自行落盘）
├── fig03_sensitivity_paramA.png            # 300dpi 产物
├── figures_manifest.json
└── 改图指南.md
```

| 项                | 规则                                                                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 命名              | `fig{NN}_{slug}`：`NN` 为图号补零两位，`slug` 为 **ASCII 小写 + 下划线** 语义名（禁中文、禁空格、禁大小写混排）；`no`/`file`/`script`/`data` 四者同 slug |
| 图号              | manifest 的 `no` 保持 **`figN`** 纯编号（`fig1`/`fig2`…，全文连续）。机检按 `no` 取号，语义名只出现在 `file`/`script`/`data_entrypoint`                  |
| `file` 语义       | **相对 `figures/`**（如 `fig03_sensitivity_paramA.png`，不带 `figures/` 前缀）                                                                           |
| `script` 语义     | **相对项目根**（如 `figures/scripts/fig03_sensitivity_paramA.py`）                                                                                       |
| `data_entrypoint` | **相对项目根**（如 `figures/data/fig03_sensitivity_paramA.json`）                                                                                        |
| 路径分隔符        | manifest 内路径**一律正斜杠 `/`**；`verify.py` 与 `gate_audit.py` 两侧均归一化，写入反斜杠视为不规范                                                     |

**脚本内定位（硬性规范）**：必须用 `__file__` 相对定位，禁止相对 cwd 或硬编码绝对路径。

```python
from pathlib import Path
ROOT = Path(__file__).resolve().parents[2]          # figures/scripts/x.py → 项目根
OUT  = Path(__file__).resolve().parents[1]          # → figures/
```

> 既有正确范式：`run_all.py` 顶层常量 `ROOT = os.path.dirname(os.path.abspath(__file__))`，以及 `validate_output_directory()` 里的 `skill_root = Path(__file__).resolve().parent`。
> ⚠️ `run_all.py` 的 `_demo_plot_and_register_figures()` 里两处 `Path(__file__)`（读 record、存 png）**不是**范式——那是写给 `figN.py` 的**字符串模板**，不是 run_all 自身的路径逻辑。
> 不这么做，"空 cwd 独立运行"（验收②(a)）必挂。

**双布局边界（判定顺序）**：解析 `script`/`data_entrypoint` 时 **先按分层路径找**（`figures/scripts/…`、`figures/data/…`）→ **再按扁平路径找**（`figures/figN.py`、`figures/figN.json`）→ **两处都不存在 = FAIL**。
兼容扁平只为不打断既有 demo；**"放错目录"必须被抓到**，不得因为兼容扁平面放过。

## 三、图脚本硬规范

| #   | 规范                                                                                                 | 机检                                             |
| --- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 1   | **独立可运行**：`python figures/scripts/figXX.py` 在**空 cwd** 下跑通并产出 PNG，不依赖 `run_all.py` | `stage_gate.py` 验收②(a)（子进程空 cwd 跑）      |
| 2   | **300dpi** PNG 落盘到 `figures/{slug}.png`                                                           | `validate_figures.py` RASTER-DPI                 |
| 3   | **禁 rainbow/jet/hsv**                                                                               | `validate_figures.py` COLOR-MAP                  |
| 4   | **中文字体**（SimHei/微软雅黑/SimSun），负号正常                                                     | `validate_figures.py` CN-FONT                    |
| 5   | **`__file__` 定位**（见 §二）                                                                        | `validate_figures.py` 新增项「脚本可运行」       |
| 6   | **CONTRACT 块**（见 §四），含 `data_binding` + `plot_calls`                                          | `validate_figures.py` 静态；`stage_gate.py` 动态 |
| 7   | **禁统计推断**（见 §六）                                                                             | AST + 运行时守卫                                 |
| 8   | 显式字号 ≥10pt（正文/轴标签级）                                                                      | `validate_figures.py` FONT-SIZE                  |

```bash
python "<SKILL_ROOT>/scripts/validate_figures.py" figures/scripts/fig03_sensitivity_paramA.py
python scripts/validate_figures.py <绘图脚本>.py   # 静态预检：中文字体/禁rainbow/DPI≥300/采样记录
```

`validate_figures.py` PASS/WARN/FAIL 三级；FAIL 必须修，WARN 人工确认，`--strict` 时 WARN 也算不通过。
⚠️ **静态预检不校验渲染效果**，图好看不好看、对不对，只能靠 §八 目视检查。

## 四、CONTRACT 元数据（脚本内，格式精确）

```python
CONTRACT = {
    "fig_id": "fig03_sensitivity_paramA",
    "data_binding": {
        # 数据源限定：q1 阶段 results/q1_results.json；final 阶段 results/results.json
        "results_path": "results/q1_results.json",
        # 绘图参数名 -> results 键名（只设两段，唯一口径）
        "bindings": {
            "y":    "Q1_基线_耗时",
            "yerr": "Q1_基线_耗时_std",
        },
    },
    "plot_calls": [{
        "method": "bar",
        "data_params": ["x", "y"],        # 统一用「参数名」，不用索引
        "kwarg_params": ["yerr"],         # kwarg 也用名字
        "aux_params": ["x_labels"],       # 坐标/装饰，排除比对
    }],
}
```

### 4.1 只设两段映射，不设第三段

- `bindings` **左值 = 绘图参数名**（matplotlib 侧，如 `y`、`yerr`）
- `bindings` **右值 = results 键名**（如 `Q1_基线_耗时`）
- 中间**不设**"脚本 dict 键"这一段

**为什么不用「脚本 dict 键」**：`visualizer.py` 的 `_errorbar()` 读的是 `d["err"]`，传给 matplotlib 时形参叫 `yerr=`——**捕获侧只看得到 `yerr`**。若把右值写成脚本 dict 键 `err`，捕获到的 `yerr` 就找不到对应键，比对直接失效。以**捕获侧命名**为准，冲突消失。

### 4.1.1 检验类图的推荐画法（参考，不强制）

做检验可视化时优先考虑：**龙卷风图**（单参数灵敏度排序）、**箱线图**（3 次重复实验的离散度）、
**残差图**（拟合误差是否随机分布，用于判断模型是否漏掉系统性偏差）、**收敛曲线**（迭代法）。
选哪种由数据形态定，不硬套——**图是为说明问题，不是为凑数**（见 §一 三条纪律）。

### 4.2 寻址与判定规则

| 字段             | 含义                                           | 比对行为                                              |
| ---------------- | ---------------------------------------------- | ----------------------------------------------------- |
| `data_params`    | 位置参数名（按调用顺序）                       | 须在 `bindings` 找到 results 键，**逐值匹配**         |
| `kwarg_params`   | 关键字参数名                                   | 同上                                                  |
| `aux_params`     | 坐标/刻度/装饰（`x` 刻度、类别标签、轨迹坐标） | **排除比对**（本就不来自 results）                    |
| **未声明的入参** | 三个列表都没提到的绘图入参                     | **`WARN` 列出，不静默放过**；`--strict` 时视为 `FAIL` |

### 4.3 来源限定

| 阶段  | 唯一来源                  | 说明                                        |
| ----- | ------------------------- | ------------------------------------------- |
| q1    | `results/q1_results.json` | `workflow.py` 的 `publish_q1()` 产出的 Q1 权威产物             |
| final | `results/results.json`    | `run_all.py` 的 `run_pipeline()` 末尾写入 |

> **同名三义提醒**：`workflow.py` 的 `publish_q1()` 会把 `q1_results.json` 复制进快照并**改名**为 `results.json`（`shutil.copyfile(result_path, snapshot / "results.json")`）。q1 阶段**明确读 `q1_results.json`**，不读 `results.json`。
> **收紧说明**：旧字段 `data_source`（自由字符串）允许指向任意文件（含 demo 的 `figures/fig1.json`）；新契约限定**只认上述两个路径**。

### 4.4 两个字段的分工

| 字段           | 类型       | 读者     | 强制性                                                                              |
| -------------- | ---------- | -------- | ----------------------------------------------------------------------------------- |
| `data_source`  | 自由字符串 | **人读** | 保留（既有人工溯源线索）                                                            |
| `data_binding` | 结构化     | **机检** | **新增必填**：进 `register_figure` 签名 + `gate_audit` 必填键循环（**11 → 12 键**） |

## 五、捕获面表（验收③ 的核心）

`stage_gate.py` 以 monkeypatch matplotlib 的方式捕获**实际绘图入参**，再经 `CONTRACT.data_binding` 解析回 `results/` 键值逐值比对。
下表按 `visualizer.py` 的 **11 个绘图方法**逐一列举（`_line/_bar/_scatter/_box/_heatmap/_hist/_errorbar/_contour/_contourf/_radar/_fill_between`）。

| 方法                                                              | 捕获                         | 依据（`visualizer.py`）                                          |
| ----------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------- |
| `Axes.plot(x, y)`                                                 | 位置参数                     | `_line:176` / `_radar:251` / `_fill_between:265`                 |
| `Axes.bar(x, y, yerr=)`                                           | 位置参数 **+ `yerr` kwarg**  | `_errorbar:213` —— **误差棒在此，不在 `Axes.errorbar`**          |
| `Axes.errorbar`                                                   | 位置参数 + `yerr`            | 契约允许的未来用法（v2.0 全库无调用）                            |
| `Axes.boxplot(data)`                                              | 位置参数                     | `_box:191`                                                       |
| `Axes.fill(angles, vals)`                                         | 位置参数                     | `_radar:252`                                                     |
| `Axes.fill_between(x, lo, hi)`                                    | 三个位置参数                 | `_fill_between:266`                                              |
| `Axes.axhline(y)` / `Axes.axvline`                                | 位置参数                     | 基线参考线 `_errorbar:220` / `_fill_between:268`                 |
| `Axes.text(x, y, s)`                                              | 位置参数 + 文本              | 图内数值标注 `_errorbar:217`                                     |
| `Axes.scatter` `:185` / `Axes.hist` `:204` / `Axes.imshow` `:196` | 位置参数                     | `_scatter` / `_hist` / `_heatmap`                                |
| `Axes.contour` `:227`、`:240` / `Axes.contourf` `:236`            | 位置参数                     | `_contour` / `_contourf`                                         |
| `Axes.barh` / `Axes.pcolormesh`                                   | 位置参数（`barh` 加 `xerr`） | 契约允许的未来用法（v2.0 全库无调用），体例同 `Axes.errorbar` 行 |

**口径说明**：

- `Axes.grid` / `set_xticks` / `set_xlabel` / `set_ylim` / `legend` / `colorbar` / `clabel` **不在捕获面**——它们是坐标与装饰，不进比对。
- `_radar` 的 `angles`、`_contour` 的 `meshgrid(X, Y)`、`_box` 的组标签属**计算/装饰量**，应列入 `aux_params`。
- `_errorbar` 的 `hatch`、`capsize`、`color` 是样式 kwarg，**不列入** `data_params`/`kwarg_params`。
- **运行时守卫必须早于后端锁定**：monkeypatch 要在 `matplotlib.use("Agg")`（`visualizer.py` 顶层，import 时执行）**之前**预载，否则拿到的是已锁定后端下的对象。

## 六、禁统计推断（AST + 运行时守卫）

**原则**：作图脚本只做**呈现**，不做**推断**。统计量必须由编程手算好落盘。

| 层             | 手段                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 静态 AST       | 匹配 `np.std/var/percentile/quantile/corrcoef`、`scipy.stats.*`、`scipy.optimize.curve_fit/least_squares`、sklearn `.fit()/.predict()` |
| 豁免           | 注释 `# STATS-EXEMPT: <非空理由>` + CONTRACT 的 `statistical_exempt`；**空理由 FAIL，非空理由降 WARN**                                 |
| **运行时守卫** | 子进程预载 monkeypatch，把上述函数替换为**抛异常**；`getattr`/`eval`/`__import__` 拿到的是**同一个被 patch 的对象** → 动态绕过无效     |
| **职责边界**   | 统计量（**含误差棒**）由**编程手算好落盘**，作图手**只读常量**                                                                         |

`statistical_exempt` 写法（逐调用）：

```python
# STATS-EXEMPT: 绘图需要按 1.5×IQR 裁掉离群点以稳定 y 轴范围，截断规则不进入任何结论
```

**自动入口**：接入 `stage_gate.py`，不靠手跑。

> **诚实说明**
> AST 只能"降概率"，抓不到拼接字符串、`getattr`、把统计算在配置文件里等路径；**真判据在运行时守卫 + 职责边界**。
> 若编程手把 std 算进 `results`、作图手读取即合规——**这是设计意图，不是漏洞**：误差棒的正确性归编程手的门禁2a，作图手只负责"把给定的数画对"。把这条边界写清楚，是为了让"信息从哪个字段来"可审计，而不是把统计能力当违规来抓。

## 七、manifest 状态机

```
incomplete ──补齐必需字段(作图)──→ pending_verification
pending_verification ──脚本跑通产出PNG(脚本自写)──→ reproduced
reproduced ──独立审查通过(审查)──→ verified
```

| 状态                   | 谁写                  | 触发条件                                    | 附带的强制字段                                                                    |
| ---------------------- | --------------------- | ------------------------------------------- | --------------------------------------------------------------------------------- |
| `incomplete`           | 作图 Agent            | 缺必需字段即停在（`missing_evidence` 非空） | —                                                                                 |
| `pending_verification` | 作图 Agent            | 必需字段齐全                                | —                                                                                 |
| `reproduced`           | **脚本自写**          | 脚本跑通并产出 PNG                          | `artifact_hash = sha256(脚本 + 数据入口 + PNG)`                                   |
| `verified`             | **只由审查 Agent 写** | 独立审查通过                                | `reviewer` 非空 + `reviewer != 作图Agent` + `evidence_hashes` + `criteria_sha256` |

**状态不脱钩**：`artifact_hash` 三元组（脚本 / 数据入口 / PNG）**任一变化自动退回 `pending_verification`**。改脚本、改数据、重跑生成不同 PNG，都必须重新走到 `reproduced`。

**`verified` 照既有强模式校验**（对齐 `gate_audit.validate_review` 的口径）：

- `reviewer` 非空，且 **`reviewer != 作图 Agent`**
- evidence 文件逐一 hash 存 `evidence_hashes`
- `criteria_sha256` 匹配**冻结基线**

**哈希外部锚**：`artifact_hash` 同时记入**审查侧** `docs/log_审查.md`。作图 Agent 单方面重写 manifest 的状态或哈希 → 与审查侧记录不符 → **FAIL**。

> **诚实说明**
> 审查 Agent 与作图 Agent 都是 AI 扮演，「reviewer 非空」本身**不构成独立性的证明**。真独立性来自**证据哈希外部锚**（审查侧独立记录）+ **`criteria_sha256` 绑定冻结基线**。
> 哈希能防「手改状态」，**不能防「数据编造」**——若编程手落盘的 `results` 本身就是编的，哈希照样一致。后一条只能靠 §五 的插桩比对（证明"画进图里的数 = results 里的数"）与人审判断。

## 八、目视检查（硬性门槛）

**作图 Agent 每张图产出后必须实际打开查看**（跑完脚本 ≠ 完成）。逐图检查：

| #   | 检查项                    |
| --- | ------------------------- |
| 1   | 数值与图注一致            |
| 2   | 坐标轴标签含单位          |
| 3   | 图例完整、不遮挡数据      |
| 4   | 无裁切、无溢出            |
| 5   | 灰度可辨                  |
| 6   | 色盲可辨                  |
| 7   | 中文无乱码、负号正常      |
| 8   | 面板编号正确（(a)(b)(c)） |

- 检查记录写入 **`docs/log_作图.md`**（发现的问题 + 修正）
- **门禁2b 的审查 Agent 必须独立看图**，不得只看作图 Agent 的记录（防自证）
- **独立性证据物**：审查 Agent 在 `docs/log_审查.md` 须写下**作图 Agent 记录中未出现的观察项**（哪怕是"无异样"也要写成逐图独立结论）；若与作图 Agent 的记录**完全一致且无独立观察**，视为**未独立查看**
- **机检不能替代目视**：`validate_figures.py` 是静态预检，`stage_gate.py` 是数值比对，**都不证明图"好看且正确"**
- 同理：**优秀论文扫描页、最终 PDF 也必须实际看**（`执行与交付契约.md` §5「扫描件查看原页」强化为强制）

> **诚实说明**
> 审查 Agent 也是 AI，其 log 同样可编造。本条的独立性**弱于** §七 的哈希外部锚——它靠的是"独立观察项"这一可核对的痕迹，**不构成强证明**。彻底防自证只能靠人工复核。

## 九、与其他文件的关系

| `图契约.md`              | **画图前怎么想**：五问 / hero 面板 / 反冗余 / 图分类（按用途）                                    |
| `图表规范.md`            | **图怎么画**：选图决策表（§一 权威）/ 受控配色（§三 权威）/ 硬性格式                              |
| **本文件**               | **图怎么被机器验证**：分类与豁免 / 分层 / 脚本规范 / CONTRACT / 捕获面 / 统计禁令 / 状态机 / 目视 |
| `改图指南.md`            | 改图时图号 → 脚本 → 数据字段 → 重跑命令 → `stage_gate` 的对照表                                   |
| `执行与交付契约.md` §3   | 官方资料与可复现交付（每图交代码/数据入口/图片/运行方式/版本/种子/官方示例链接及修改理由）        |
| `Subagent质检.md` 门禁2b | 审查侧验收（脚本独立运行 / 无统计推断 / 契约齐全 / 数值一致 / 目视检查）                          |

```bash

python "<SKILL_ROOT>/scripts/stage_gate.py" --project "<赛题目录>" --stage final
```
