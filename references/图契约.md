# 图契约 —— 画图前必读

> 现行阶段、来源、创新、人工声明及交付边界见 `执行与交付契约.md`；原细则在当前阶段范围内执行，不代替团队第一问批准或全文独立终审。

> 借鉴 nature-figure（nature-skills，Apache-2.0，见 NOTICE.md）的 **Figure Contract** 思想，适配数模国赛。
> 核心：**每张图是一个视觉论证，不是孤立的漂亮图**。画图前先写契约（证明什么、证据从哪来、什么图、编号、图题），再写代码。先结论后画图，杜绝"画完了不知道图想说什么"。

## 一、画图前五问（必答，AI 画图前逐条登记）

| #   | 问题                            | 要求                                                                                                                                                        |
| --- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **这张图要证明什么？**          | 一句话带动词。如"改进算法使调度耗时降低 12.68%"，不是"结果对比"                                                                                             |
| 2   | **证据从哪个 results 字段来？** | 图上结果数据按指标/单位/条件可溯源到 `results/` 字段，轴刻度另按定义核验（事实铁律）。v3.0 落地载体是脚本内 `CONTRACT.data_binding`（见 `作图契约.md` §四） |
| 3   | **选什么图类型？**              | 见 `图表规范.md` §一 选型决策表；不硬套折线/柱状                                                                                                            |
| 4   | **图编号？**                    | `fig1/fig2...` 连续，与正文引用一一对应（图题在图下）                                                                                                       |
| 5   | **图题怎么写？**                | 图题在图下方，含结论要点（评审一眼抓重点）                                                                                                                  |

> 代码登记：`Visualizer.register_figure(no, title, conclusion, data_source, ...)` → `figures/figures_manifest.json`（v3.0 起再增 `data_binding`，见 `作图契约.md` §四）。
> 机器检查：`verify_figure_references`（图号连续/正文引用对应/图文件存在）；状态机与数值一致由 `stage_gate.py` 查。

## 三、受控配色（权威规范见 `references/图表规范.md` §三）

> 速记：**蓝 = 本文方法 / 红 = 基线 / 绿 = 改进**（`PALETTE`），禁 rainbow/jet/hsv。
> 完整色板、灰度可读、hatch 约定见 `图表规范.md` §三，此处不重复。

```python
from math_modeling import PALETTE   # {"method","baseline","improve",...}
ax.bar(..., color=PALETTE["method"], hatch="//", label="本文方法")
ax.axhline(baseline, color=PALETTE["baseline"], ls="--", label="基线")
```

## 四、hero 面板 + 布局（多面板图）

- **一张图一个主叙事**：核心证据占 hero 面板（最大/最清晰），从属面板（灵敏度/鲁棒性）视觉上安静
- 多面板用 `gridspec`，**避免等大子图**（证据权重不同）；legend 独立面板或共享一条，不重复
- 机理示意图：AI 按 process_record 思考轨迹画"模型结构/流程"示意图，标注物理量；图题写清"示意图说明建模机理"
- 面板字母 `a/b/c` 左上加粗小写；图题在图下（国赛规范）

### 图分类四类（诊断图按验证价值选择用途）

借鉴 zhnnky329/MathModeling-skills 的图分类思路，画前先定图归哪类：

| 类         | 内容                                         | 进不进论文                             |
| ---------- | -------------------------------------------- | -------------------------------------- |
| **诊断图** | 过程/探索/中间结果（收敛过程、数据分布探索） | 有验证价值可入正文或附录，纯探索留记录 |
| **对比图** | 方案/算法/基线对比                           | 进论文（有真实对照证据）               |
| **论文图** | 最终关键结果                                 | 进正文，图题含结论要点                 |
| **附录图** | 完整输出/大表图                              | 放附录                                 |

> **两个分类维度正交**：本表按**用途**分；`作图契约.md` §一 按**可机检性**分（数据图 / 示意图）。每张图两个标签都要定——用途决定进不进论文，机检类型决定是否豁免数值比对（示意图须显式写 `kind: "schematic"`，不写按数据图全查）。

## 五、反冗余检查（画完自查）

- [ ] 每个面板答**独立**问题；遮住任一面板，论证有缺口吗？
- [ ] 不重复展示同一数据（绝对占比 + 相对偏差要分开，用 z-score 偏差视图）
- [ ] 每块面板有自己的坐标轴含义（x/y 量纲不同才放一起）
- [ ] 柱图原则从零起，折线等可合理缩放并明确刻度，不夸大差异

## 六、QA 校验（交付前）

```bash
python scripts/validate_figures.py <绘图脚本>.py    # 静态预检：中文字体/禁rainbow/DPI≥300/采样记录
python "<SKILL_ROOT>/scripts/stage_gate.py" --project "<赛题目录>" --stage q1
```

- `validate_figures.py`：PASS/WARN/FAIL 三级；FAIL 必须修，WARN 人工确认（v3.0 新增 4 项：脚本可运行 / 数据入口存在 / 契约字段含 `data_binding` / 无统计调用，见 `作图契约.md` §三）
- `verify_figure_references`（run_pipeline 自动跑）：图号连续、正文引用对应、图文件存在 —— issues 进 process_record 人工审核
- 每张图最终 `figures/*.png`（300dpi），与论文 `images` 字段一一对应
- **脚本硬规范、目录分层、状态机、目视检查**见 `作图契约.md` §二/§三/§七/§八

## 七、契约块（写脚本时的格式）

v3.0 起，图的契约**直接写在脚本内的 `CONTRACT` 块**（含 `fig_id` / `data_binding` / `plot_calls`），不再用手写 `results.json:字段` 字符串代替。
完整格式与映射口径见 **`作图契约.md` §四**；脚本硬规范见 §三；捕获面（哪些绘图入参必须能对上 `results` 键）见 §五。
